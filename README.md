# Markdown → PPT 转换说明书

> **这份文档是施工手册，不是项目介绍。**
> 手上有一份别的 Markdown（笔记、方案、讲义、公众号稿、旧课件），要把它转成这套紫金风格
> 幻灯片（marp + `themes/nju.css`）时，照着它改。全文的写法都是：
>
> **源文件里是什么 → 要改成什么 → 为什么。**
>
> 想先看改完长什么样，翻 `examples/theme-preview.md`（所有元素总览）和
> `examples/code-preview.md`（代码块用法）。
>
> ⚠️ **两条最容易翻车的铁律，先记住：**
>
> 1. **每页只能用 `-` 和 `1.` 列列表。** 用 `*` 或 `1)`，条目会变成"按一次键才出来一个"。
> 2. **每页固定 1280×720，超出部分被静默裁掉**，不报错、不警告 —— 改完必须在预览里
>    从头翻到尾。

**这份文档的规则全部对着 `themes/nju.css` 的真实实现写**（正文 22px、`##` 29px 加粗、
图片高度上限四档……）。如果哪天改了主题，记得回来同步这里。

## 0. 怎么用这份说明书

一次完整的转换，按这个顺序走：

| 步骤 | 去哪里看 | 做什么 |
| --- | --- | --- |
| ① 跑起来 | [第 2 节](#2-环境与命令) | 建好目录，起预览 |
| ② 逐条改 | [第 3 节](#3-逐条改造规则) | 把源 md 的写法换成幻灯片写法（**主战场**） |
| ③ 查容量 | [第 4 节](#4-一页能放得下多少) | 一页塞不下时怎么砍 |
| ④ 排版面 | [第 5 节](#5-布局类速查) | 分两栏 / 紧凑 / 整页图 |
| ⑤ 自检 | [第 6 节](#6-转换完成自检清单) | 对着清单过一遍 |
| ⑥ 导出 | [第 2 节 → 导出](#导出) | 出 PPTX / PDF |

**只需要记一条工作流：**

```
源 md  ──改──▶  decks/xxx.md  ──预览──▶  从头翻到尾  ──▶  导出
                    ▲                        │
                    └──────── 改 ────────────┘
```

## 1. 转换流程（五步）

**第 1 步 · 归位。** 把源 md **复制**一份到 `decks/` 下（原件留在原地，别直接改），
图片拷到 `decks/assets/`。文件名建议就用幻灯片主题，例如 `decks/2026-新生刷题方案.md`。
`decks/` 进 git，改坏了能回滚。

**第 2 步 · 改造。** 按第 3 节逐条过：分页、标题层级、列表符号、图片路径……
这一步决定了 80% 的最终观感，**不要跳过**。

**第 3 步 · 预览翻页。** 起预览，**从头翻到尾**，一页一页看有没有被裁掉的、
有没有哪页比别页挤。

**第 4 步 · 修溢出。** 挤的页面按第 4 节的顺序处理：精简 → `cols2` → `compact` → 拆页。
（Marp 溢出是静默的，只能靠肉眼翻。）

**第 5 步 · 自检 + 导出。** 过第 6 节清单，然后敲 marp 导出 PPTX / PDF。

## 2. 环境与命令

### 目录结构

```
ppt-md/
├─ README.md                      ← 本文档（转换说明书）
├─ start-marp-preview.bat         实时预览脚本（唯一的脚本）
├─ themes/nju.css                 主题：配色 / 字号 / 图片上限都在这里
├─ examples/                      参考稿与自检稿
│  ├─ theme-preview.md            所有元素长什么样（拿它当"样板间"）
│  ├─ code-preview.md             代码块用法
│  └─ assets/                     自检稿用的示意图
└─ decks/                         ← 转换产物放这里（没有就自己建），进 git
   ├─ 你的幻灯片.md
   └─ assets/                     幻灯片用的图片，跟 deck 一起进 git
```

**图片一律放 deck 旁边的 `assets/`，用相对路径引，不要用图床 URL**
（断网 / 图床挂了 / 导出 PDF 时会变成空白框，见 3.9）。

### 预览

```bat
start-marp-preview.bat "decks\2026-新生刷题参考方案及检查要求.md"
```

浏览器自动打开这一份 deck。之后改 markdown、保存，页面自动刷新（热加载）。

```bat
start-marp-preview.bat "decks\xxx.md"        rem 预览这一份
start-marp-preview.bat "C:\anywhere\x.md"    rem md 放哪都行
```

- 主题**固定**用本目录的 `themes/nju.css`，所以 markdown 放在哪里都行，也不必写 `theme:` 头。
- **停止预览**：关掉那个标题为 `Marp Preview` 的窗口（或在窗口里按 `Ctrl+C`）。
  脚本前台运行，没有后台残留、没有 pid 文件。

**脚本在干什么：**

```bat
cd /d "<deck 所在目录>"                          rem 以 deck 所在目录为服务根，本地图片才找得到
set "PORT=8080"                                  rem 固定端口，URL 才能预测
start "Marp Preview" marp -s -w . --theme "<本目录>\themes\nju.css"
ping -n 3 127.0.0.1 >nul                         rem 等服务器起来
start "" "http://localhost:8080/<deck 文件名>"   rem 直接打开 deck 本身，而不是目录列表页
```

- **`-s`（服务器模式）是关键：磁盘上不留任何文件。**
  `-p`（preview）不管怎么调都一定会写一个 `.html`（默认写在 md 旁边，指定 `-o`
  就写到 `-o` 指的地方），永远有文件要清理；`-s` 只在内存里渲染。
- `-w` 盯着目录，保存即重渲染；`-s` 不会自己开浏览器，所以脚本自己开。
- **端口固定 8080**：marp 服务器模式只读环境变量 `PORT`（**没有 `--port` 参数**，
  读不到就用 8080）。固定端口脚本才能拼出确定的 URL。
  **8080 被占了，新预览会起不来**，报 `Listen port 8080 is already used` ——
  多半是上一个预览窗口没关，关掉它再跑一次。
  确实要换端口：改脚本里那行 `set "PORT=8080"`（或先 `set PORT=9090` 再手动跑 marp）。

### 导出

导出**不**在脚本里，需要时自己敲 marp：

> `marp ".\presentation.md --theme ".\C:\Users\hello\myRespository\ppt-md\themes\nju.css" --pptx --allow-local-files`

```bat
marp "decks\xxx.md" --theme themes\nju.css --pptx          --allow-local-files
marp "decks\xxx.md" --theme themes\nju.css --pdf           --allow-local-files
marp "decks\xxx.md" --theme themes\nju.css --images png    --allow-local-files
marp "decks\xxx.md" --theme themes\nju.css -o out.html
```

> **`--allow-local-files` 一定要加（导出 HTML 除外）。** Marp 出于安全默认不允许
> 导出时读本地文件，不加这个参数，deck 里引用的本地图片在 PDF / PPTX / PNG 里会
> **变成空白**，而且不报任何错。图床 URL 不受影响 —— 这也是很多人没发现的原因。
> 预览不需要它：服务器模式是通过 HTTP 取图的。

> **导出比预览慢得多**：导出要新起一个 headless Chrome 逐页渲染，Chrome 冷启动
> 本身就 ~5s。13 页 deck 实测 PPTX 约 9s、PDF 约 11s，这是 marp 用 puppeteer 的
> 固有成本，不是配置问题。

**关于 PPTX**：marp 默认导出的 PPTX 是**每页一张图片**（不可编辑，字体不会跑版）。
要可编辑的版本加 `--pptx-editable`（官方标记为实验特性，排版会走样，谨慎用）。

**不写 `--pptx` / `--pdf` / `--images` 时，输出默认是 HTML。**
另外 `--html` 这个参数**不是"输出 HTML 格式"**，而是"允许 markdown 里写 HTML 标签"
（预览脚本没有加它，所以 **deck 里不要依赖 HTML 标签**，见 3.11）。

### deck 的 front-matter（开头那段 `---`）

推荐每份 deck 开头只写这一件有用的事：

```markdown
---
paginate: true
---
```

- **`paginate: true` 才有右下角页码**（`1/12` 那种）。不写就没有页码。
- `theme:` 不用写 —— 脚本和导出命令都用 `--theme` 指定了 `themes/nju.css`。
- `marp: true` 只在用 VS Code 的 Marp 插件预览时才需要，命令行转不转跟它无关。
- **源文档自带的 front-matter（`title:` / `date:` / `tags:` / 博客头）请删掉**，
  它们会被 Marp 当成指令解析，轻则无用，重则改掉当页样式。

## 3. 逐条改造规则

> 这一节是转换的主战场。所有"源文档 → 幻灯片"的格式变动都在这里。
> 每条都标了**为什么**，知道原因才不会改错方向。

### 3.0 一图流总览

| 源文档里是什么 | 直接渲染成什么 | 要改成什么 |
| --- | --- | --- |
| 普通段落 | 22px 深灰正文 | 保留，一段 1~2 行 |
| `#` 文档大标题 | **页面顶部紫色标题栏** | 每页重排：一页只有一个 `#` |
| `##` 章节标题 | 页内主标题 29px 加粗 | 用来切本页的小节 |
| `###` 小节 | 页内小节 25px 加粗 | 嵌套最多两层 |
| `- 条目` / `1. 条目` | 正常列表 | 保留，**首选这两种** |
| `* 条目` / `1) 条目` | **逐条按键才出现** | **必须改成 `-` / `1.`** |
| `**加粗**` | **砖红色**，不是加粗 | 每页只留 1~2 处 |
| `> 引用` | 浅边框提示框 + 紫 ◆ | 一页一个，放结论/注意事项 |
| 段落后面紧跟列表或提示框 | 那个段落变**紫色小标签** | 有意的，别写错（见 3.3） |
| `---` / `***` / `___` | **全部变成分页** | 源文档的分隔线必须删掉 |
| 代码块 | 灰底、长行自动换行 | ≤16 行，只留核心片段 |
| 表格 | 有边框的小表 | ≤4 列 × ≤6 行 |
| 图片 | 自动限高、独占一页会放大 | 一张图一页；本地 `assets/` 相对路径 |
| `[文字](url)` | 深灰下划线 | 每页 ≤10 个 |
| YAML front-matter | 被当成 Marp 指令 | 清掉，只留 `paginate: true` |
| `[^1]` 脚注 | **变成指向脚注文本的坏链接** | 改成括号内说明 |
| `- [ ]` 任务列表 | 原样显示 `[ ]` | 改成普通 `-` 列表 |
| `<img>`、`<div>` 等 HTML | 默认被丢掉（预览没开 `--html`） | 改写 Markdown 原生写法 |
| `$公式$` / `$$公式$$` | MathJax 正常渲染 | 可用，但一页别放多个块级公式 |
| mermaid / 图表代码块 | 不渲染，显示成一段代码 | 先导出成 PNG，再当图片插入 |
| 目录 / TOC | 一堆链接 | 删掉，或单独做一页大纲 |

### 3.1 分页

源文档是"连续长文"，没有"页"的概念 —— 分页是转换时**新加的信息**。

- 用 `---` 分页，**前后各留一个空行**。
- 分页单位是**一个意思**，不是"一段"：一页 = 一个标题 + 一组要点 + 一句结论。
- **源文档里的分隔线（`---` / `***` / `___`）在幻灯片里全部会变成分页符。**
  正文中间的 `***` 会把这一页拦腰截断。转换时**看到就删**。
- 源文档开头的 YAML front-matter 也是 `---` 包起来的，照抄会把整个头部吃掉或切页。

```markdown
## 源文档（连续长文）          ## 幻灯片（分页后）

引言……                          # 第三章：递归
                                 
***                             这里写本章要说什么。
                                 
第三章 递归                     ---
                                 
3.1 基本概念                     # 第三章：递归
……                              ## 3.1 基本概念
```

### 3.2 标题层级：每页有且只有一个 `#`

| 写法 | 用途 | 渲染 |
| --- | --- | --- |
| `# 标题` | **每页的页面标题** | 顶部紫色标题栏里的白字（35px 加粗） |
| `## 标题` | 页内主标题 | 大号深色字（29px 加粗） |
| `### 标题` | 小节 | 中号深色字（25px 加粗） |

**转换动作**：源文档的 `#` 是"整篇的大标题"，`##` 是章。**别照搬层级**，
要在每一页里重新分配：

- 每一页**有且只有一个 `#`**，它就是这一页的标题（标题栏）。
- 标题别超过 **16 个汉字**，长了会顶到标题栏边缘。
- **没有 `#` 的页面会自动隐藏标题栏** —— 适合封面、章节分隔页、总结页。
  想一直显示标题栏，就删掉 `themes/nju.css` 里 `section:not(:has(h1))` 那两条规则。
- `####` 及以下主题**没有专门样式**（`####` 只有正文那么大，`#####` / `######` 更小），
  转换时**降到 `###` 或改成列表**。
- 源文档里那种"第一页大标题 + 副标题 + 作者 + 日期"的开头，就是一个**封面页**：
  写 `# 大标题`，副标题放它下面那段（自动变浅灰），日期可以省掉。

```markdown
# 第三阶段：递归、搜索与树        ← 标题栏

建议周期：第 6-7 周               ← # 之后的第一段，自动变成浅灰副标题
目标：理解递归、DFS、BFS、二叉树遍历。

## 七、二叉树                     ← 页面主标题
```

### 3.3 副标题与引导词（自动样式，别手写）

`#` 后面**第一个段落**会被自动渲染成**浅灰副标题**，适合写"建议周期 / 目标"这类前缀说明。

**例外**：这段文字后面**紧跟列表或提示框**时，会被当成**引导词**，渲染成**紫色小标签**：

```markdown
基础题：                    ← 自动变紫色小标签

1. 两数之和
2. 存在重复元素

代理工具                    ← 后面跟提示框也一样

> clash
> v2rayN
```

- **不需要**加粗、不需要写任何标记，直接写成一行文本即可。
- 两种写法（后面接列表 / 后面接提示框）渲染**完全一致**，同一个页面里混用不会花。
- **反过来的坑**：一段正常正文后面直接跟提示框，那段文字会被当成标签变小变紫。
  想避免就把正文放进提示框里，或者在两者之间插一个 `##`。
- 源文档里那种"小标题 + 下面一段说明文字"的结构，很适合改成"引导词 + 列表"。

### 3.4 列表

- 每项**一行写完**，不要写成两三行的长句 —— 那不是列表，是段落。
- 项与项之间**结构要平行**（都是名词、或都是动词短语）。
- 单页超过 8 项就考虑分两栏：页面开头加 `<!-- _class: cols2 -->`。
- 嵌套最多两层，三层以上换成 `###` 小节。

**推荐**

```markdown
- 哈希表查找
- 前缀和
- 计数数组
```

**避免**

```markdown
- 哈希表查找，这是在处理需要快速判断元素出现过时的常用技巧，通常配合字典实现
```

#### ⚠️ 只能用 `-`，不要用 `*`

这一条最容易踩，而且后果很明显：

| 写法 | 切幻灯片时的表现 |
| --- | --- |
| `- 条目` | **整页一次性全部显示** ✓ |
| `+ 条目` | 整页一次性全部显示 ✓ |
| `* 条目` | **每一项要按一次键才出来** ✗ |
| `1. 条目` | 整页一次性全部显示 ✓ |
| `1) 条目` | 每一项要按一次键才出来 ✗ |

**原因**：Marpit 源码里写死了

```js
const fragmentedListMarkups = ['*', ')'];
```

用 `*`（无序列表）或 `1)`（有序列表）作标记的列表，会被当成 **fragmented list**，
每个 `<li>` 被加上 `data-marpit-fragment` 属性，条目就变成"按键才出现一个"。

`-`、`+`、`1.` 不会。**没有任何开关能关掉它，主题 CSS 也管不了** ——
只能在 markdown 层面避开 `*` 和 `1)`。

> **批量修法**：把行首的 `* ` 换成 `- `、行首的 `1) ` 换成 `1. ` 即可
> （只影响行首，`**加粗**`、`*斜体*` 不受影响）。
> 源文档如果是从 Typora / 飞书 / 语雀搬来的，几乎一定有 `*`，**转换时全局搜一遍**。

### 3.5 强调：`**红色**`

`**加粗**` 渲染成**砖红色**（`#a8232c`），**不是**加粗变黑。

```markdown
怎么把一件大事，在**人和工具的共同协作**下做成?
```

**转换时要注意**：源文档里"满篇加粗"（技术文档特别常见）会变成"满篇红字"，
等于没有重点。**规则：**

- 一页最多强调 **1~2 处**。
- 强调的应该是**关键词**（3~8 字），不是整句话。
- 想要加粗的视觉效果而不是红色，用 `###` 小节代替。
- 源文档里的 `__下划线加粗__`、`<b>` 标签：统一改成 `**`，或按上一条删掉。

### 3.6 提示框：`> 引用`

`>` 引用会渲染成**浅边框提示框 + 紫色文字 + 紫色 ◆ 前缀**，
适合放"一句话结论""注意事项""易错点"。

```markdown
> 工程能力，是在稀疏、延迟的反馈下仍能维持方向。
```

- ◆ 是**主题自动加的**，markdown 里**不要**手打 `◆`（会变成两个）。
- 一页最多一个提示框，放在页面底部收尾效果最好。
- 里面可以放 `**强调**`、`` `代码` `` 和链接（都会跟着变紫）。
- **转换动作**：源文档里的大段引用（论文引用、多段摘录）**不要整段搬** ——
  提示框会变得又长又紫。只留**一句结论**，其余删掉或另起一页。
- 提示框**前面紧挨着一个段落**时，那个段落会被当成**引导词**（紫色小标签，见 3.3）。
  这是有意的；但如果那是完整句子，就把它放进提示框里，或者前面加个 `##`。
- 源文档的多行引用（`>` 里好几个段落）在幻灯片里会挤成一个高框，建议拆成两页或改成列表。

### 3.7 代码块

代码块**不会自动缩小字号**（那是 Marp 默认行为，会把长行缩到 5px 看不清，
本主题已关闭）。改为**长行自动换行**。

**规则：**

| 项 | 建议 |
| --- | --- |
| 行数 | **≤ 16 行**（含标题），超了拆页 |
| 单行长度 | **≤ 80 字符**；再长会换行，虽然能看但很丑 |
| 内容 | 只放**核心片段**。完整实现放仓库，别贴 PPT |
| 注释 | 中文注释会正常换行，但**要短** |
| 语言标注 | 一定要写（```` ```python ````），才有语法高亮 |

**推荐**

````markdown
```python
def lower_bound(a, target):
    left, right = 0, len(a)
    while left < right:
        mid = left + (right - left) // 2
        if a[mid] < target:
            left = mid + 1
        else:
            right = mid
    return left
```
````

**避免**：一页贴 40 行完整解法；单行超过 120 字符。

**转换动作**：源文档里成百行的完整代码/配置文件，**挑 5~10 行最关键的**贴出来，
其余在页面上写一句"完整实现见仓库 <路径>"。一页 16 行的预算很紧，别浪费。
行内 `` `代码` `` 可以保留（浅紫底），也适合放命令、文件名、字段名。

### 3.8 表格

- 列数 **≤ 4**，行数 **≤ 6**。
- 单元格内容要短，最多 10 个汉字。
- 表头用名词，别写句子。
- 表格天然不会被裁，但列太宽会被挤到换行，很难看。

**转换动作**：源文档里的宽表（5 列以上）、长表（十几行）、带长句的单元格，
**拆**成几个 ≤4 列的小表，或者干脆改成列表：

```markdown
| 方案（源文档宽表）        | 幻灯片改法                     |
| --- | --- |
| 5 列以上                  | 拆成两个表，或改成 `-` 列表     |
| 8 行以上                  | 拆成两页，每页一个 `##`         |
| 单元格是整句话            | 取关键词，细节留给讲解          |
```

### 3.9 图片

图片只有一条硬规矩：**一张图，一页，不要和正文挤在一起。**（图很小、只当图标用的除外。）

Marp 的默认主题只给图片加了宽度上限，**没加高度上限** —— 竖版长截图会一路顶到
720px 之外被静默裁掉，"图跑到画布最下面"、"图被切掉了"都是这么来的。
本主题把它补上了：图片只会被缩小，永远不会超出画布。

**高度上限分四档，按"这一页还有什么"自动选：**

| 这一页的样子 | 图的高度上限 |
| --- | --- |
| 还有别的正文（列表、段落、代码…） | **380px** |
| 只有 `#` 标题 + 这张图 | **561px** |
| 只有这张图（没写 `#`） | **618px** |
| 加了 `<!-- _class: img-full -->` | **640px**（写了 `#` 时 566px） |

所以**放一张大图最省事的写法就是"图单独一页，什么都不写"**，主题会自动认出
"这一页只有图"并把它放到最大：

```markdown
---

![](assets/sakura.png)
```

再大一点、或者图下面还想放一行图注，就加整页图类：

```markdown
---

<!-- _class: img-full -->

![](assets/sakura.png)

*图 1：SakuraCat 的套餐页面*
```

**图片路径（转换时的必做动作）**

- **把源文档的远程图片下载到本地**，放进**幻灯片旁边的 `assets/` 目录**，用相对路径引用：
  `decks/foo.md` 引用 `decks/assets/bar.png` → 写 `![](assets/bar.png)`。
  别用图床 URL —— 断网、图床挂了、导出 PDF 时都会变成空白框。
- 建议每个 deck 一个自己的 `assets/`，跟着 deck 一起进 git。
- 源文档里的 `![图](https://...)`、`<img src="https://...">` 都要改成本地相对路径。

**把图改小 —— 只有一种写法：给图片写尺寸**

```markdown
![w:600](assets/sakura.png)     宽度 600px（最常用）
![h:200](assets/sakura.png)     高度 200px，宽度等比跟着变
```

- 单位是 px，**不支持百分比** —— `![w:50%]()` 会被 Marp 整个丢掉，等于没写，
  图还是原样大小。这是最容易踩的一个坑。
- **不要同时写 `w:` 和 `h:`**（`![w:900 h:200]()`）：两个都写就是强制拉伸成那个形状，
  图会被压扁。只写一个，另一个自动等比。
- 竖图（手机截图、长流程图、竖版海报）**用 `h:` 最直观**。写 `w:` 时如果等比算出来的
  高度超过了上表的上限（比如竖图写 `w:1000`），图会被按比例压回来，宽度也跟着缩水 ——
  这种情况改用 `h:`，图会比现在大。
- 反过来想让图**更大**，就别写尺寸：让它独占一页，主题会自动放到最大。

`w:` / `h:` 只负责"改小"，永远压不过上表的高度上限，也不会让图横向溢出。

**其它排版**

- 图片**独占一个段落**会自动居中；一个段落里并排放多张图会自动留出间隔。
- 图片下一行写 **`*斜体*`** 会自动变成居中的浅灰**图注**。
- 图片**尽量别放进列表项**里 —— 会被列表缩进挤成一条窄带。
  真要放，就把图单独提一页。

**从 Typora / 飞书笔记搬过来的图**

那两个编辑器给图片加的是 `style="zoom:67%"`，这**不是 Marp 认的写法**（Marp 只认
alt 文字里的 `w:` / `h:`），所以搬过来之后尺寸会变回"原始大小"。
改写成 `![w:600](x.png)` 这种写法。

### 3.10 链接

链接是**深灰 + 下划线**（和参考稿一致）。

- 一页链接**别超过 10 个** —— 满屏下划线很吵。
- 链接文字要**有含义**（`[两数之和](...)`），不要贴裸 URL。
- 观众点不了投影上的链接，链接主要是给你自己 / 导出 PDF 后用的。

**转换动作**：源文档（尤其技术文档）末尾那一大串"参考资料 / 参考链接"
**整段删掉**，或者浓缩成 2~3 个最关键的放在最后一页。裸 URL 一律改成有含义的文字。

### 3.11 源文档里"不该带进来"的东西

转换时最花时间的往往不是排版，而是**清理源文档的痕迹**。逐项对照：

| 源文档里的东西 | 实际会怎样 | 怎么改 |
| --- | --- | --- |
| YAML front-matter（`title`/`date`/`tags`） | 被 Marp 当指令解析 | 删掉，只留 `paginate: true` |
| `---` / `***` / `___` 分隔线 | **变成分页**，把页面拦腰截断 | 删掉（要分页就明确用 `---` 分页） |
| 目录 / TOC（一堆锚点链接） | 满屏下划线的链接 | 删掉，或做成单独一页大纲 |
| 脚注 `[^1]` + 定义 | **坏链接**（`^1` 指向脚注正文），定义行消失 | 改成括号内说明，或直接删 |
| 任务列表 `- [ ]` / `- [x]` | 原样显示 `[ ]`，没有勾选框 | 改成普通 `-` 列表 |
| HTML 标签（`<img>`、`<div>`、`<details>`、`<br>`） | **默认被整个丢掉**（预览脚本没加 `--html`） | 改写成 Markdown 原生写法 |
| `<!-- 注释 -->` 当正文用 | 不显示 | 删掉（`_class` 指令用的注释除外，那条是有效的） |
| mermaid / plantuml 代码块 | 不渲染，显示成一段代码 | 先导出成 PNG，再当图片插 |
| 数学公式 `$...$`、`$$...$$` | MathJax 能正常渲染 | 可用；但一个块级公式约占 1/3 页，一页最多一个 |
| 徽章、emoji 满屏 | 能显示，但很吵 | 精简，只留必要的 |
| `> [!NOTE]` 这类 GitHub 提示语法 | 按普通引用渲染（紫框） | 可用，但别指望有图标 |
| 锚点/相对链接（`[见 x](#y)`） | 跳转失效 | 删掉，或在文字里直接说明 |

**还有一个常见来源**：源文档是"连续编号"结构（`1.` `2.` `3.` 一路到底），
幻灯片里**不要保留这个编号** —— 每页都从 `1.` 重新开始，或者干脆不用序号。

## 4. 一页能放得下多少

### 硬上限

画布 1280×720，扣掉标题栏和上下留白，**正文区只有 561px 高、1180px 宽**。

| 项目 | 占多高 | 上限 |
| --- | --- | --- |
| 正文一行 | ≈ 38px | 单栏**约 11~13 行**，两栏翻倍 |
| 列表项（含间距） | ≈ 43px | 单栏**约 11 项**为宜，两栏**约 22 项** |
| `##` 主标题 | ≈ 48~68px | 每页建议 1 个，最多 2 个 |
| `###` 小节 | ≈ 70px | 尽量少用 |
| 代码块 | ≈ 26px/行 | **≤ 16 行** |
| 一行文字长度 | — | 单栏 **≤ 45 汉字**，两栏每栏 **≤ 24 汉字** |

> 38px ≈ 1 行正文、43px ≈ 1 个列表项，可以拿这两个数估"超了几行"。
> 估不准就数一下这一页正文有几行。

### 超了怎么办（按这个顺序试）

1. **精简文字** —— 九成的问题靠删字解决。列表项压成一行，段落砍成一句话。
2. **加 `cols2`** —— 页面开头写 `<!-- _class: cols2 -->`，列表分两栏，高度直接砍半。
   （适合"每项都很短"的清单；长句子分栏后会很难读。）
3. **加 `compact`** —— 字号 22px → 20px、行高 1.74 → 1.5，一页能多放 4~5 行。
4. **拆页** —— 一个意思一页，拆出来的两页往往比挤成一页更好讲。

> **不要**一上来就 `compact`。字号一页大、一页小，翻页时会很跳。
> 优先删字和拆页，`compact` 只用来救"差一两行"的情况。

### 为什么溢出是静默的

Marp 的每一页都是固定 1280×720 加 `overflow: hidden`，**内容超出会被静默裁掉** ——
不报错、不警告、导出也不提示。所以：

- **唯一的检查手段是"在预览里从头翻到尾"。** 不翻一遍就永远不知道丢了什么。
- 翻到某一页明显比别人挤，就按上面四步处理。

> 本主题做了两件事让问题**可见**：关闭 Marp 的 auto-scaling（代码块不再被缩成
> 蚂蚁字）、禁止 flex 子项被压缩（放不下就是真的溢出到画布外，能一眼看出来）。

## 5. 布局类速查

写在**页面最前面**（`#` 标题之前），只影响当页：

```markdown
---

<!-- _class: cols2 -->

# 这一页的标题
```

| 写法 | 效果 | 什么时候用 |
| --- | --- | --- |
| `<!-- _class: cols2 -->` | 顶层列表分成左右两栏 | 列表 ≥ 8 项；短条目清单 |
| `<!-- _class: compact -->` | 字号 22→20，行高 1.74→1.5 | 加了两栏还是差几行 |
| `<!-- _class: cols2 compact -->` | 两者叠加 | 内容特别多 |
| `<!-- _class: img-full -->` | 一页只放一张大图，图上限 380→640px | 流程图、架构图、长截图（见 3.9） |

**注意：**

- `cols2` 只对**顶层列表**生效，嵌套在 `li` 里的子列表不会跟着分栏。
- `compact` 会同时收紧 `#` 之外的各处间距（`##` / `###` / 段落 / 提示框），
  标签页整体变小，所以别和相邻页混着用。
- `img-full` 那一页**不要写 `#`**，图会从标题栏位置开始；确实要标题栏就写 `#`，
  主题会自动把图往下让 78px（上限相应降到 566px）。

## 6. 转换完成自检清单

**格式（源文档遗留问题）**

- [ ] **所有列表都用 `-` 或 `1.`，没有一个 `*` 或 `1)`**（否则切页时条目会一个个跳）
- [ ] 源文档的 `---` / `***` / `___` 分隔线已清掉（没在正文中间多分页）
- [ ] 源文档的 YAML front-matter 已清掉，只留 `paginate: true`
- [ ] 脚注、任务列表 `[ ]`、目录 TOC、HTML 标签**都已改写或删除**
- [ ] 源文档的"1. 2. 3."连续编号没有照搬到页面上

**版式（主题规则）**

- [ ] 在预览里**从头翻到尾**，没有哪一页被裁掉（Marp 溢出是静默的）
- [ ] 每页**只有一个 `#`**，标题不超过 16 个汉字
- [ ] 没有一页超过 11~13 行正文（或两栏 22~26 行）
- [ ] 代码块不超过 16 行，单行不超过 80 字符，都写了语言标注
- [ ] 表格 ≤ 4 列 × ≤ 6 行，单元格 ≤ 10 个汉字
- [ ] 一页最多 1~2 处 `**红色强调**`
- [ ] 一页最多一个 `>` 提示框，且里面没有手打 `◆`
- [ ] 段落后面紧跟列表/提示框的地方，是**有意**做成紫色小标签的

**图片**

- [ ] **图片没有塞在列表项里**，也没有和正文挤一页
- [ ] **图片用的是本地 `assets/` 相对路径**，不是图床 URL
- [ ] 从 Typora / 飞书搬来的图，`style="zoom:…"` 已经改写成 `![w:…]()`
- [ ] 竖图没有写 `w:` 却被上限压回（该用 `h:`）
- [ ] 没有同时写 `w:` 和 `h:`（会把图压扁）

**交付**

- [ ] 链接不超过 10 个，且都是"有含义的文字"
- [ ] 预览里翻页时没有明显的字号跳变（`compact` 用多了会有）
- [ ] 导出时带了 `--allow-local-files`，导出后图片都在

## 7. 常见问题

**Q：内容太多，一页放不下怎么办？**

按顺序试：① 精简文字 ② 加 `cols2` 分两栏 ③ 加 `compact` ④ 拆成两页。
溢出是**静默**的，只能自己在预览里翻一遍看，别凭感觉。

**Q：源文档里的 `*` 列表怎么批量改？**

把行首的 `* ` 替换成 `- `。**只替换行首**（正则 `^\* `），否则 `**加粗**` 会被误伤。
有序列表把行首的 `1) ` 换成 `1. `。改完在预览里翻一遍，确认没有"按键才出现"的页。

**Q：为什么我的表格/代码块显示不全？**

Marp 每页 `overflow: hidden`，超出的部分不报错、直接裁掉。
代码块已修好（长行自动换行、不缩字号）；表格和超长英文单词仍可能横向溢出 ——
在预览里把这一页翻出来目视检查，列太宽就精简单元格或拆页。

**Q：提示框里出现了两个 ◆？**

因为你在 markdown 里手打了 `◆`。删掉它，主题会自动加。

**Q：我的图跑到画布最下面、还被切掉了？**

两个原因，按顺序排：

1. 图**不在自己的一页上**，而且太高。Marp 默认只限制图片宽度、不限制高度，
   所以长截图会一路顶穿画布被裁掉。本主题已经加了高度上限，但和正文挤一页时
   只有 380px —— 把图单独放一页，它会自动放大到 561~618px。
2. 图是**用图床 URL** 引的，导出时没加载出来。改成旁边的 `assets/` 相对路径。

**Q：图太大，怎么把它改小？**

给图片写尺寸，只有这一种写法：

```markdown
![w:600](assets/sakura.png)     宽度 600（最常用）
![h:200](assets/sakura.png)     高度 200，竖图用这个
```

详见 3.9。三件常踩的事：`![w:50%]()` **不支持百分比**，会被 Marp 整个丢掉
（图看起来"改不小"就是这个原因）；同时写 `w:` 和 `h:` 会把图压扁；
想让图**更大**反而什么都别写 —— 让它独占一页。

**Q：竖图写了 `w:1000`，怎么没变大？**

你写的宽度按等比算出来的高度超过了这一页的高度上限，主题把图按比例压回来了 ——
图没坏也没被裁，只是比你要的小。竖图改用 `![h:...]`，或者把图单独放一页。

**Q：明明在 Typora 里调好了图片大小，到这儿就变回原样了？**

Typora 用的是 `style="zoom:67%"`，Marp 只认 alt 里的 `w:` / `h:`。
改写成 `![w:600](x.png)`。

**Q：图片和文字能不能并排？**

不建议。这一页会同时压低字数上限和图的尺寸，两边都憋屈。
把图放一页、文字放一页，或者用 `> 提示框` 在图下写一句结论。

**Q：公式、脚注、任务列表、mermaid 支持吗？**

- 公式 `$...$` / `$$...$$`：**支持**，MathJax 渲染。块级公式很占地方，一页最多一个。
- 脚注 `[^1]`：**不支持**，会变成指向脚注正文的坏链接 —— 改成括号内说明。
- 任务列表 `- [ ]`：**不渲染勾选框**，只会原样显示 `[ ]` —— 改成普通列表。
- mermaid：**不渲染**，会显示成一段代码 —— 先导出成 PNG 再当图片插。
- HTML 标签：预览脚本没开 `--html`，**会被丢掉** —— 改成 Markdown 写法。

**Q：导出 PDF / PPTX 之后图片全没了 / 变成空白框？**

导出时漏了 `--allow-local-files`。Marp 默认禁止导出时读本地文件，
**本地图片会被静默丢掉**（图床 URL 不受影响，所以很难自己发现）。加上就行：

```bat
marp "decks\xxx.md" --theme themes\nju.css --pdf --allow-local-files
```

**Q：导出的 PPTX 里文字改不了？**

marp 默认导出的 PPTX 是**每页一张图片**，不能编辑（好处是字体绝不跑版）。
要可编辑的版本改用 `--pptx-editable`（实验特性，排版会走样）。

**Q：改完保存了，预览没反应？**

按顺序查：

1. 浏览器标签是不是还连着 —— 页面里的自动刷新是靠 WebSocket，标签页被休眠/断线时
   刷新 `F5` 一下就好。
2. 你保存的是**服务器服务的那个目录里的那份文件**（服务器根目录就是传给脚本的那个
   deck 所在目录）。
3. 导出/查看的是另一个副本（比如 `decks/xxx.md` 和桌面上的 `xxx.md` 是两份文件）。
4. 跑预览的那个窗口还在不在 —— 关了窗口服务器就没了。

**Q：`Listen port 8080 is already used`？**

端口被占了（常见于另一份 deck 的预览还在跑）。marp 服务器模式只认环境变量 `PORT`，
**没有 `--port` 参数**。最省事的做法：**关掉旧的 `Marp Preview` 窗口，再跑一次**。
确实要换端口，就改脚本里的 `set "PORT=8080"`（或先 `set PORT=9090` 再手动跑 marp）。

**Q：怎么知道现在有没有预览在跑、怎么停？**

看哪个窗口里还印着 `[Server mode] Start server listened at ...`。
关掉那个窗口，或在**那个窗口按 `Ctrl+C`**。脚本前台运行，所以没有后台残留、
没有 pid 文件，也不用记 `--stop` 之类的命令。

**Q：想让某页不显示紫色标题栏？**

删掉那页的 `#` 标题即可（封面、章节页、总结页常用）。

**Q：想改配色？**

改 `themes/nju.css` 顶部 `:root` 里的 CSS 变量，改完保存，预览自动刷新。
但**不要改**字号、行高、左右留边 —— 那会破坏和参考稿的一致性。

**Q：怎么回滚到以前的版本？**

```bat
git log --oneline --decorate
git checkout <某个提交>
git checkout main
```

## 8. 主题参数（想改观感改哪里）

改配色、字号都在 `themes/nju.css` 顶部的 `:root` 里。

| 项目 | 值 |
| --- | --- |
| 画布 | 1280 × 720（16:9） |
| 标题栏 | 78px 高，紫色渐变 |
| 页面标题 `#` | 35px 白色加粗 |
| 主标题 `##` | **29px 加粗** `#1f1f1f` |
| 小节 `###` | 25px 加粗 |
| 正文 | **22px** / 行高 1.74（一行 ≈ 38px） |
| 紧凑模式 `compact` | 正文 20px / 行高 1.5 |
| 正文字色 | `#414141` |
| 强调色 | `#a8232c`（砖红） |
| 主题紫 | `#6e4890` / 深紫 `#5b298c` |
| 提示框文字 | `#7d5fae` + 1px `#ececf0` 边框 |
| 页码 | 12px `#aaa`，右下角（需要 front-matter `paginate: true`） |
| 左右留白 | 50px（正文宽 1180px） |
| 上下留白 | 上 113px / 下 46px（正文区高 561px） |
| **舒适线** | **内容底边 674px**（超过只是挤占下边距，超过 720 才真被裁） |
| 图片高度上限 | 混排 380px / 图独占一页 561~618px / `img-full` 640px（见 3.9） |

**保持这个观感的关键**：正文 22px、行高 1.74、左右 50px。
这几个值是和参考稿逐像素对齐的（误差 ±1px），**不要随便改**。

> **标题字重注意**：`#` / `##` / `###` 现在是 **全部加粗**（35 / 29 / 25px）。
> 早先 `##` 是 32px **常规字重**，那是照着 `examples/` 里那张截图定的；
> 换成新参考稿后改成 29px 加粗 —— **加粗才是这套观感的关键**，
> 只把字号调小不加粗，看起来会"软"很多。
