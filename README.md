# md-ppt

用 Markdown 写幻灯片，用 marp 实时预览，导出成和 `examples/` 里参考稿一致的紫金风格 PPT。

- **写**：普通 Markdown，`---` 分页
- **看**：一条命令起 marp 服务器，改完自动刷新
- **导出**：需要时直接敲 marp（命令见下）

---

## 快速开始

```bat
start-marp-preview.bat "decks\2026-新生刷题参考方案及检查要求.md"
```

浏览器会自动打开这一份 deck。之后改 markdown、保存，页面自动刷新（热加载）。

```bat
start-marp-preview.bat "decks\xxx.md"        rem 预览这一份
start-marp-preview.bat "C:\anywhere\x.md"    rem md 放哪都行
```

主题**固定**用本目录的 `themes/nju.css`，所以 markdown 放在哪里都行，也不必写 `theme:` 头。

**停止预览**：关掉那个标题为 `Marp Preview` 的窗口。

### 脚本在干什么

```bat
cd /d "<deck 所在目录>"
set "PORT=8080"
start "Marp Preview" marp -s -w . --theme "<本目录>\themes\nju.css"
ping -n 3 127.0.0.1 >nul
start "" "http://localhost:8080/<deck 文件名>"
```

- **`-s`（服务器模式）是关键：磁盘上不留任何文件。**
  `-p`（preview）不管怎么调都一定会写一个 `.html`（默认写在 md 旁边，指定 `-o`
  就写到 `-o` 指的地方），永远有文件要清理；`-s` 只在内存里渲染。
- `-w` 盯着目录，保存即重渲染
- `-s` 不会自己开浏览器，所以脚本自己开，并且**直接打开 deck 本身**，
  而不是服务器的目录列表页
- **端口固定 8080**：marp 服务器模式读环境变量 `PORT`（**没有 `--port` 参数**）。
  固定端口，脚本才能拼出确定的 URL。如果 8080 被占（多半是上一个预览窗口没关），
  新服务器会起不来 —— 关掉旧的 `Marp Preview` 窗口再跑一次。

### 导出

导出**不**在脚本里，需要时自己敲 marp：

```bat
marp "decks\xxx.md" --theme themes\nju.css --pptx          --allow-local-files
marp "decks\xxx.md" --theme themes\nju.css --pdf           --allow-local-files
marp "decks\xxx.md" --theme themes\nju.css --images png    --allow-local-files
marp "decks\xxx.md" --theme themes\nju.css --html
```

> **`--allow-local-files` 一定要加（导出 HTML 除外）。** Marp 出于安全默认不允许
> 导出时读本地文件，不加这个参数，deck 里引用的本地图片在 PDF / PPTX / PNG 里会
> **变成空白**，而且不报任何错。图床 URL 不受影响 —— 这也是很多人没发现的原因。
> 预览不需要它：服务器模式是通过 HTTP 取图的。

> **导出比预览慢得多**：导出要新起一个 headless Chrome 逐页渲染，Chrome 冷启动
> 本身就 ~5s。12 页 deck 实测 PPTX 约 5–6s、PDF 约 7–10s，这是 marp 用 puppeteer
> 的固有成本，不是配置问题。

## 目录结构

```
md-ppt/
├─ README.md                      ← 本文档（写作规范）
├─ start-marp-preview.bat         实时预览（唯一一个脚本）
├─ themes/nju.css                 主题（改配色/字号在这里）
├─ examples/                      示例与自检稿
│  ├─ theme-preview.md            主题自检稿：所有元素长什么样（含图片各档）
│  ├─ code-preview.md             代码块用法示例
│  └─ assets/                     自检稿用的示意图
└─ decks/                         （需要时自己建）你的幻灯片，纳入 git 管理
   └─ assets/                     幻灯片用的图片，跟着 deck 一起进 git
```

**关于 `decks/`**：这是正式存放幻灯片的地方，有 git 历史，改坏了可以回滚。
建议以后就**直接在这里写**，不要再放到桌面到处散落。
图片放 `decks/assets/`，用相对路径引，别用图床（见第 10 节）。

## 工作流

```
写内容  →  start-marp-preview.bat 看效果  →  改  →  导出
                       ↑                      │
                       └──────────────────────┘
```

**改完一定要在预览里从头翻到尾。** Marp 的每一页都是固定 1280×720 加
`overflow: hidden`，内容超出会被**静默裁掉**，不报错、不警告 ——
不翻一遍就永远不知道丢了什么。翻到某一页明显比别人挤，就按第 3 节的顺序处理。

# 写作规范

> 下面每条都是为了让页面**好看**，不只是"能显示"。
> 参考效果见 `examples/theme-preview.md`。

## 1. 一页只说一件事

一页塞两个主题，观众记不住，而且一定会溢出。

**推荐**：一页 = 一个标题 + 一组要点 + 一句结论。
长内容就拆成两页，**不要**靠缩小字号硬塞。

## 2. 标题层级

| 写法 | 用途 | 渲染 |
| --- | --- | --- |
| `# 标题` | **每页的页面标题** | 顶部紫色标题栏里的白字 |
| `## 标题` | 页面内的主标题 | 大号深色字 |
| `### 标题` | 小节 | 中号深色字 |

**规则**：

- 每一页**有且只有一个 `#`**，它就是这个页面的标题。
- `#` 之后的第一个段落会被自动渲染成**浅灰副标题**，
  适合写"建议周期 / 目标"这类前缀说明。
  - 例外：这段文字后面**紧跟列表或提示框**时，会被当成**引导词**渲染成紫色小标签
    （见第 5 节），不会变灰副标题 —— 这两条规则的优先级是一样的，引导词那条写在后面。
- 没有 `#` 的页面会**自动隐藏标题栏**（适合封面、章节页、总结页）。
  想一直显示标题栏，就删掉 `themes/nju.css` 里 `section:not(:has(h1))` 那两条规则。
- 标题别超过 **16 个汉字**，长了会顶到标题栏边缘。

```markdown
# 第三阶段：递归、搜索与树        ← 标题栏

建议周期：第 6-7 周               ← 自动变成浅灰副标题
目标：理解递归、DFS、BFS、二叉树遍历。

## 七、二叉树                     ← 页面主标题
```

## 3. 一页能放多少（硬上限）

画布 1280×720，扣掉标题栏和上下留白，正文区只有 **561px** 高。

| 项目 | 一行/一个占 | 上限 |
| --- | --- | --- |
| 正文 / 列表项 | 45px | 单栏 **约 11 行**，两栏 **约 22 行** |
| `##` 主标题 | 51px | 每页建议 1 个，最多 2 个 |
| `###` 小节 | 40px | — |
| 代码块 | 27px/行 | **≤ 16 行** |
| 一行文字长度 | — | 单栏 **≤ 45 汉字**，两栏每栏 **≤ 24 汉字** |

超了就按顺序试：**加 `cols2` → 再加 `compact` → 拆页**。

> 40px ≈ 1 行，可以拿这个数估"超了几行"。估不准就数一下这一页正文有几行。

## 4. 列表

- 每项**一行写完**，不要写成两三行的长句 —— 那不是列表，是段落。
- 项与项之间**结构要平行**（都是名词、或都是动词短语）。
- 单页超过 8 项就考虑分两栏：在页面开头加 `<!-- _class: cols2 -->`。
- 嵌套最多两层，三层以上换成 `###` 小节。

**推荐**

```markdown
- 哈希表查找
- 前缀和
- 计数数组
```

**避免**

```markdown
- 哈希表查找，这是在处理需要快速判断元素出现过时的常用技巧，通常配合字典实现
```

### ⚠️ 只能用 `-`，不要用 `*`

这一条最容易踩，而且后果很明显：

| 写法 | 切幻灯片时的表现 |
| --- | --- |
| `- 条目` | **整页一次性全部显示** ✓ |
| `+ 条目` | 整页一次性全部显示 ✓ |
| `* 条目` | **每一项要按一次键才出来** ✗ |
| `1. 条目` | 整页一次性全部显示 ✓ |
| `1) 条目` | 每一项要按一次键才出来 ✗ |

**原因**：Marpit 源码里写死了

```js
const fragmentedListMarkups = ['*', ')'];
```

用 `*`（无序列表）或 `1)`（有序列表）作标记的列表，会被当成 **fragmented list**，
每个 `<li>` 加上 `data-marpit-fragment` 属性，条目就变成"按键才出现一个"。

`-`、`+`、`1.` 不会。**没有任何开关能关掉它，主题 CSS 也管不了** ——
只能在 markdown 层面避开 `*` 和 `1)`。

> 如果你有旧笔记大量用了 `*`，转换很简单：把行首的 `* ` 换成 `- ` 即可
> （只影响行首，`**加粗**`、`*斜体*` 不受影响）。

## 5. 引导词（"基础题："这类）

**后面紧跟列表或提示框的段落**会被自动渲染成**紫色小标签**，用来分层次。

```markdown
基础题：                    ← 自动变紫色小标签

1. 两数之和
2. 存在重复元素

代理工具                    ← 后面跟提示框也一样

> clash
> v2rayN
```

- **不需要**加粗、不需要写任何标记，直接写成一行文本即可。
- 反过来说，**不要**在段落后面留一个列表却忘了写引导词 —— 会少一层结构感。
- 两种写法（后面接列表 / 后面接提示框）渲染**完全一致**：同一个页面里混用不会花。
  反过来也要注意：一段正常正文后面直接跟提示框，那段文字会被当成标签变小变紫
  （想避免就把正文放进提示框里，或者在两者之间插一个 `##`）。

## 6. 强调：`**红色**`

`**加粗**` 渲染成**砖红色**（`#a8232c`），**不是**加粗变黑。

```markdown
怎么把一件大事，在**人和工具的共同协作**下做成?
```

**规则**：

- 一页最多强调 **1~2 处**。到处都是红字等于没有重点。
- 强调的应该是**关键词**（3~8 字），不是整句话。
- 想要加粗的效果而不是红色，用 `###` 小节代替。

## 7. 提示框：`> 引用`

`>` 引用会渲染成**浅边框提示框 + 紫色文字 + 紫色 ◆ 前缀**，
适合放"一句话结论""注意事项""易错点"。

```markdown
> 工程能力，是在稀疏、延迟的反馈下仍能维持方向。
```

- ◆ 是**主题自动加的**，markdown 里**不要**手打 `◆`（会变成两个）。
- 一页最多一个提示框，放在页面底部收尾效果最好。
- 里面可以放 `**强调**`、`` `代码` `` 和链接。
- 提示框**前面紧挨着一个段落**时，那个段落会被当成**引导词**（紫色小标签，见第 5 节）。
  这是有意的：`代理工具` + 一串提示框就是"标签 + 内容"。但如果那是完整句子，
  就把它放进提示框里，或者前面加个 `##`。

## 8. 代码块

代码块**不会自动缩小字号**（那是 Marp 默认行为，会把长行缩到 5px 看不清，
本主题已关闭）。改为**长行自动换行**。

**规则**：

| 项 | 建议 |
| --- | --- |
| 行数 | **≤ 16 行**（含标题），超了拆页 |
| 单行长度 | **≤ 80 字符**；再长会换行，虽然能看但很丑 |
| 内容 | 只放**核心片段**。完整实现放仓库，别贴 PPT |
| 注释 | 中文注释会正常换行，但**要短** |
| 语言标注 | 一定要写（```` ```python ````），才有语法高亮 |

**推荐**

````markdown
```python
def lower_bound(a, target):
    left, right = 0, len(a)
    while left < right:
        mid = left + (right - left) // 2
        if a[mid] < target:
            left = mid + 1
        else:
            right = mid
    return left
```
````

**避免**：一页贴 40 行完整解法；单行超过 120 字符。

## 9. 表格

- 列数 **≤ 4**，行数 **≤ 6**。
- 单元格内容要短，最多 10 个汉字。
- 表头用名词，别写句子。
- 表格天然不会被裁，但列太宽会被挤到换行，很难看。

## 10. 图片

图片只有一条硬规矩：**一张图，一页，不要和正文挤在一起。**（图很小、只当图标用的除外。）

Marp 的默认主题只给图片加了宽度上限，**没加高度上限** —— 竖版长截图会一路顶到
720px 之外被静默裁掉，"图跑到画布最下面"、"图被切掉了"都是这么来的。
本主题把它补上了：图片只会被缩小，永远不会超出画布。

**高度上限分四档，按"这一页还有什么"自动选：**

| 这一页的样子 | 图的高度上限 |
| --- | --- |
| 还有别的正文（列表、段落、代码…） | **380px** |
| 只有 `#` 标题 + 这张图 | **561px** |
| 只有这张图（没写 `#`） | **618px** |
| 加了 `<!-- _class: img-full -->` | **640px**（写了 `#` 时 566px） |

所以**放一张大图最省事的写法就是"图单独一页，什么都不写"**，主题会自动认出
"这一页只有图"并把它放到最大：

```markdown
---

![](assets/sakura.png)
```

再大一点、或者图下面还想放一行图注，就加整页图类（见「布局类速查」）：

```markdown
---

<!-- _class: img-full -->

![](assets/sakura.png)

*图 1：SakuraCat 的套餐页面*
```

**图片路径**

- 图片放在**幻灯片旁边的 `assets/` 目录**里，用相对路径引用：
  `decks/foo.md` 引用 `decks/assets/bar.png` → 写 `![](assets/bar.png)`。
  别用图床 URL —— 断网、图床挂了、导出 PDF 时都会变成空白框。
- 建议每个 deck 一个自己的 `assets/`，跟着 deck 一起进 git。

**把图改小 —— 只有一种写法：给图片写尺寸**

```markdown
![w:600](assets/sakura.png)     宽度 600px（最常用）
![h:200](assets/sakura.png)     高度 200px，宽度等比跟着变
```

- 单位是 px，**不支持百分比** —— `![w:50%]()` 会被 Marp 整个丢掉，等于没写，
  图还是原样大小。这是最容易踩的一个坑。
- **不要同时写 `w:` 和 `h:`**（`![w:900 h:200]()`）：两个都写就是强制拉伸成那个形状，
  图会被压扁。只写一个，另一个自动等比。
- 竖图（手机截图、长流程图、竖版海报）**用 `h:` 最直观**。写 `w:` 时如果等比算出来的
  高度超过了上表的上限（比如竖图写 `w:1000`），图会被按比例压回来，宽度也跟着缩水 ——
  这种情况改用 `h:`，图会比现在大。
- 反过来想让图**更大**，就别写尺寸：让它独占一页，主题会自动放到最大。

`w:` / `h:` 只负责"改小"，永远压不过上表的高度上限，也不会让图横向溢出。

**其它排版**

- 图片**独占一个段落**会自动居中；一个段落里并排放多张图会自动留出间隔。
- 图片下一行写 **`*斜体*`** 会自动变成居中的浅灰**图注**。
- 图片**尽量别放进列表项**里 —— 会被列表缩进挤成一条窄带。
  真要放，就把图单独提一页。

**从 Typora / 飞书笔记搬过来的图**

那两个编辑器给图片加的是 `style="zoom:67%"`，Marp 会**直接丢掉**这个 style，
所以搬过来之后尺寸是"原始大小"。改写成 `![w:600](x.png)` 这种写法。

## 11. 链接

链接是**深灰 + 下划线**（和参考稿一致）。

- 一页链接**别超过 10 个** —— 满屏下划线很吵。
- 链接文字要**有含义**（`[两数之和](...)`），不要贴裸 URL。
- 观众点不了投影上的链接，链接主要是给你自己/导出 PDF 后用的。

# 布局类速查

写在**页面最前面**，只影响当页：

```markdown
---

<!-- _class: cols2 -->

# 这一页的标题
```

| 写法 | 效果 | 什么时候用 |
| --- | --- | --- |
| `<!-- _class: cols2 -->` | 顶层列表分成左右两栏 | 列表 ≥ 8 项；短条目清单 |
| `<!-- _class: compact -->` | 字号 23→20，行高 1.74→1.5 | 加了两栏还是差几行 |
| `<!-- _class: cols2 compact -->` | 两者叠加 | 内容特别多 |
| `<!-- _class: img-full -->` | 一页只放一张大图，图上限 380→640px | 流程图、架构图、长截图（见第 10 节） |

> **不要**靠 `compact` 解决所有问题。字号一页大、一页小，翻页时会很跳。
> 优先拆页，`compact` 只用来救"差一两行"的情况。

# 排版参数速查

改配色、字号都在 `themes/nju.css` 顶部的 `:root` 里。

| 项目 | 值 |
| --- | --- |
| 画布 | 1280 × 720（16:9） |
| 标题栏 | 78px 高，紫色渐变 |
| 页面标题 `#` | 35px 白色加粗 |
| 主标题 `##` | 32px `#1f1f1f` |
| 小节 `###` | 27px |
| 正文 | 23px / 行高 1.74（一行 40px） |
| 正文字色 | `#414141` |
| 强调色 | `#a8232c`（砖红） |
| 主题紫 | `#6e4890` / 深紫 `#5b298c` |
| 提示框文字 | `#7d5fae` + 1px `#ececf0` 边框 |
| 页码 | 12px `#aaa`，右下角 |
| 左右留白 | 50px（正文宽 1180px） |
| 上下留白 | 上 113px / 下 46px |
| **舒适线** | **内容底边 674px**（超过只是挤占下边距，超过 720 才真被裁） |
| 图片高度上限 | 混排 380px / 图独占一页 561~618px / `img-full` 640px（见第 10 节） |

**保持这个观感的关键**：正文 23px、行高 1.74、左右 50px。
这几个值是和 `examples/` 里的参考稿逐像素对齐的（误差 ±1px），**不要随便改**。

- [ ] 每页**只有一个 `#`**
- [ ] 没有一页超过 11 行正文（或两栏 22 行）
- [ ] 代码块不超过 16 行，单行不超过 80 字符
- [ ] 一页最多 1~2 处 `**红色强调**`
- [ ] 一页最多一个 `>` 提示框，且里面没有手打 `◆`
- [ ] **图片没有塞在列表项里**，也没有和正文挤一页

# 常见问题

**Q：内容太多，一页放不下怎么办？**

按顺序试：① 精简文字 ② 加 `cols2` 分两栏 ③ 加 `compact` ④ 拆成两页。
溢出是**静默**的，只能自己在预览里翻一遍看，别凭感觉。

**Q：为什么我的表格/代码块显示不全？**

Marp 每页 `overflow: hidden`，超出的部分不报错、直接裁掉。
代码块已修好（长行自动换行、不缩字号）；表格和超长英文单词仍可能横向溢出 ——
在预览里把这一页翻出来目视检查，列太宽就精简单元格或拆页。

**Q：提示框里出现了两个 ◆？**

因为你在 markdown 里手打了 `◆`。删掉它，主题会自动加。

**Q：我的图跑到画布最下面、还被切掉了？**

两个原因，按顺序排：

1. 图**不在自己的一页上**，而且太高。Marp 默认只限制图片宽度、不限制高度，
   所以长截图会一路顶穿画布被裁掉。本主题已经加了高度上限，但和正文挤一页时
   只有 380px —— 把图单独放一页，它会自动放大到 561~618px。
2. 图是**用图床 URL** 引的，导出时没加载出来。改成旁边的 `assets/` 相对路径。

**Q：图太大，怎么把它改小？**

给图片写尺寸，只有这一种写法：

```markdown
![w:600](assets/sakura.png)     宽度 600（最常用）
![h:200](assets/sakura.png)     高度 200，竖图用这个
```

详见「10. 图片 → 把图改小」。三件常踩的事：`![w:50%]()` **不支持百分比**，
会被 Marp 整个丢掉（图看起来"改不小"就是这个原因）；同时写 `w:` 和 `h:` 会把图压扁；
想让图**更大**反而什么都别写 —— 让它独占一页。

**Q：竖图写了 `w:1000`，怎么没变大？**

你写的宽度按等比算出来的高度超过了这一页的高度上限，主题把图按比例压回来了 ——
图没坏也没被裁，只是比你要的小。竖图改用 `![h:...]`，或者把图单独放一页。

**Q：明明在 Typora 里调好了图片大小，到这儿就变回原样了？**

Typora 用的是 `style="zoom:67%"`，Marp 会丢掉除 `w:`/`h:` 之外的 style 属性。
改写成 `![w:600](x.png)`。

**Q：图片和文字能不能并排？**

不建议。这一页会同时压低字数上限和图的尺寸，两边都憋屈。
把图放一页、文字放一页，或者用 `> 提示框` 在图下写一句结论。

**Q：导出 PDF 之后图片全没了 / 变成空白框？**

导出时漏了 `--allow-local-files`。Marp 默认禁止导出时读本地文件，
**本地图片会被静默丢掉**（图床 URL 不受影响，所以很难自己发现）。加上就行：

```bat
marp "decks\xxx.md" --theme themes\nju.css --pdf --allow-local-files
```

**Q：改完保存了，预览没反应？**

按顺序查：

1. 浏览器标签是不是还连着 —— 页面里的自动刷新是靠 WebSocket，标签页被休眠/断线时
   刷新 `F5` 一下就好。
2. 你保存的是**服务器服务的那个目录里的那份文件**（服务器根目录就是传给脚本的那个
   deck 所在目录，脚本启动时会打印出来）。
3. 导出/查看的是另一个副本（比如 `decks/xxx.md` 和桌面上的 `xxx.md` 是两份文件）。
4. 跑预览的那个窗口还在不在 —— 关了窗口服务器就没了。

**Q：`Listen port 8080 is already used`？**

端口被占了（常见于另一份 deck 的预览还在跑）。脚本自己会往 8081、8082… 找空闲端口，
看到这条报错说明它是从 8080 找到 8089 都被占了 —— 手动换一个更靠后的：

```bat
start-marp-preview.bat "decks\xxx.md" --port 9090
```

**Q：怎么知道现在有没有预览在跑、怎么停？**

看哪个窗口里还印着 `[Server mode] Start server listened at ...`。
在**那个窗口按 Ctrl+C** 就停了。脚本前台运行，所以没有后台残留、没有 pid 文件，
也不用记 `--stop` 之类的命令。

**Q：想让某页不显示紫色标题栏？**

删掉那页的 `#` 标题即可（封面、章节页、总结页常用）。

**Q：想改配色？**

改 `themes/nju.css` 顶部 `:root` 里的 CSS 变量，改完保存，预览自动刷新。
但**不要改**字号、行高、左右留边 —— 那会破坏和参考稿的一致性。

**Q：怎么回滚到以前的版本？**

```bat
git log --oneline --decorate
git checkout <某个提交>
git checkout master
```
